How much of a real brain can you delete before it stops working?

A fruit fly's entire brain has been mapped, neuron by neuron. I loaded all of it, 139,248 neurons and about 2.7 million connections, into a browser tab as a spiking network, then started deleting it. Nothing is trained. Whether the fly can still escape, steer, walk, hear or mate is decided by the wiring alone.

01

Five behaviours, one wiring diagram.

The FlyWire project mapped every neuron and synapse in an adult fly's brain from electron microscopy. That map is enough to simulate: give each neuron a simple spiking model, let the synapses carry the signals, and see what the network does.

I picked five behaviours with known circuits: escaping a looming threat, steering toward a target, walking and turning, hearing a courtship song, and accepting a mate. Each test drives the circuit's real sensory neurons and reads its real output neurons. Then I deleted parts of the brain and ran all five again.

02

Making 139,248 neurons fit in a tab.

AOnly simulate what's awake.

Most of the brain is at rest at any moment. The simulator only updates neurons whose state has moved, so the cost follows activity, not brain size. A whole-brain test takes about 0.3 to 1 second.

CostIt's an approximation: a neuron that drifts below a tiny threshold stops being updated until something wakes it.

BA compact binary, not JSON.

The connectome ships as a sparse matrix with 16-bit weights, about 21 MB for the browser instead of roughly 2 GB of raw data.

CostThe files are built locally, not committed, so a fresh clone needs one build step.

COne worker per behaviour.

Each of the five tests runs in its own Web Worker, all at once. That's what keeps the self-running demo to about 20 seconds a loop.

CostFive copies of the network in memory. Fine on a laptop, heavy on an old phone.

DKeep the network out of a seizure.

The published model, run on the whole brain, ran away into constant firing. A ceiling on synaptic drive and spike-frequency adaptation keep it stable.

CostThat's a departure from the published model, and the README says so.

EThe same model twice.

Python produces the results tables; JavaScript runs the live demo. They implement the same equations, so the demo shows the same thing the tables measured.

CostTwo implementations to keep in sync.

Scores are relative to the intact brain. Escape barely notices anything. Steering dies when you remove a small set of hub neurons, or half the brain.

Then I asked the opposite question: what's the smallest set of neurons that still works? Escape needs 316, and none of them are interneurons: about 300 looming detectors wired straight to the giant fiber. Accepting a mate needs four.

04

Being honest about a model.

After I posted it, someone read the results as “most of the brain is useless.” That's not what they show. Deleting the mushroom body changes nothing here because none of these five tests needs learning or memory, not because the mushroom body doesn't matter.

So I added a section to the README called “Caveats, stated plainly”: this is a model, not a fly; a null result says nothing about what a region is for; “redundant” means wide and shallow wiring, not wasted. Writing what the results don't mean turned out to be as important as the results.

05

What I'd do differently.

  • Write the caveats before launch, not after. The first readers will find the misreading you didn't rule out.
  • Measure the browser, not just the science. I know how long a test takes; I never benchmarked frame rate across devices.
  • Share one network across workers. A shared buffer would cut memory to a fifth.
